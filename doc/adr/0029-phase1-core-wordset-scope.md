# ADR-0029: フェーズ1のスコープを「Forth然とした日本語Forth」＝ANS Forth COREワードセット相当に確定

## Status

Proposed

## Context

Umor Playground（ADR-0027）の完成を機に、フェーズ1をどこまでの
スコープとするかが改めて議題に上った。

これまでのADR群（特にADR-0023）は「日本語としての自然さを
実装コストが過大でない限り優先する」という設計原則を確立して
きたが、これは主に**構文**（助詞の扱い、送り仮名正規化など）に
関する方針であり、**語彙の網羅性**（どこまでのFORTHワードを
実装するか）については明確な基準がなかった。

議論の結果、フェーズ1の到達目標を次のように言語化した：
**「Forth然とした日本語Forth」＝ANS Forthの CORE word set相当の
語彙を一通り実装すること**。ただし、以下は明確にスコープ外とする：

- **メタプログラミング寄りの機能**（イミディエイトワード、
  ユーザー定義マクロ）：ADR-0004で既にフェーズ1不採用と決定
  済み。本ADRはこれを「フェーズ2で本格検討する」候補として
  改めて位置づける。
- **リターンスタック関連**（`>R`/`R>`）：データスタックとは別に
  もう1本スタックを評価器に持たせる構造的変更が必要であり、
  単なる語彙追加とは性質が異なるため、フェーズ1の今回のスコープ
  からは除外し、別途検討する。

既存の基本ワード一覧（ADR-0017）と、ANS Forth COREセットを
突き合わせた結果、以下のスタック操作系ワードが未実装であると
判明した。これらの命名を会話ベースで検討し、決定した。

## Decision

### 1. フェーズ1のスコープ方針

フェーズ1は「ANS Forth CORE word set相当の語彙を実装した、
Forth然とした日本語Forth」を到達目標とする。メタプログラミング
機構（ADR-0004）およびリターンスタック操作（`>R`/`R>`）は
フェーズ1のスコープには含めず、フェーズ2以降で再検討する。

### 2. 新規スタック操作ワードの追加

| Forth相当 | Umor表記       | 引数順・仕様                                                                                                                                   |
| --------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `pick`    | `摘み`         | 1-origin。`n 摘み`でn番目（1が現在のトップ）の値を複製してトップに積む。`1 摘み`は`複製`と等価。                                               |
| `roll`    | `転`           | 1-origin。`n 転`でn番目の値をその場から移動し、トップに積む（`回転`は固定的に上位3つを回すのに対し、こちらは任意の深さを指定できる一般化版）。 |
| `2drop`   | `二捨`         | トップ2つをまとめて捨てる。                                                                                                                    |
| `2dup`    | `二複製`       | トップ2つをペアで複製する（`a b → a b a b`）。                                                                                                 |
| `2swap`   | `二交換`       | 上位2組（4要素）をペア単位で入れ替える（`a b c d → c d a b`）。                                                                                |
| `nip`     | `取替捨`       | `swap drop`相当の合成語（`a b → b`）。                                                                                                         |
| `tuck`    | `取替越`       | `swap over`相当の合成語（`a b → b a b`）。                                                                                                     |
| `depth`   | `深さ`         | 現在のデータスタックの要素数を数値として積む。                                                                                                 |
| `.s`      | `スタック表示` | データスタックを消費せず、内容を表示する（非破壊的）。表示順の詳細は実装時に決定する。                                                         |

いずれも既存の「数値＋語幹」パターン（`加`・`引`等と同型）、
または既存ワードの単純な合成として実装できる見込みであり、
パーサー・トークナイザへの構文拡張は不要。

### 3. `交換`/`取替`の重複整理

ADR-0017の基本ワード一覧棚卸しの過程で、`swap`相当のワードが
`交換`・`取替`の2つ、実装側の判断で重複して追加されていたことが
判明した。この整理はADR-0030（エイリアス機構）を使って解決する。
`取替`を正式な本体ワードとし、`交換`はそのエイリアスとする。
具体的な宣言はADR-0030を参照。

## Consequences

**得られるもの**：

- 「フェーズ1のゴールはどこか」という問いに、ANS Forth CORE
  word setという外部の具体的な基準で答えられるようになる。
  今後の実装作業（RosettaCodeタスク等）で、ある処理が「フェーズ1
  で足りるはずのワードだけで書けるか」を判断しやすくなる。
- 新規追加した9ワードにより、Forthのイディオム（スタック
  シャッフルパターン）をUmorでも素直に表現できる範囲が広がる。
- `交換`/`取替`の重複が、削除ではなくエイリアス機構の実例として
  正式に解消される。

**トレードオフとして受け入れるもの**：

- `摘み`（pick）・`転`（roll）の1-origin対応（`1つめ`＝トップ）は、
  Forthの`0 pick`＝トップという規約とはズレがある。Umorの既存の
  0-origin原則と日本語の「1つめ」という自然な言い方の間で、
  今回はこの形に決着した。将来この不整合が問題になる可能性は
  残る。
- `取替越`（tuck相当）は動作をそのまま合成語にした命名であり、
  英語の`tuck`が持つ「差し込む」という原義のニュアンスは
  反映されていない。実装の一貫性（`交換`＋`越え`の合成として
  一意に決まる）を優先した結果である。
- リターンスタック関連ワードを先送りしたことで、「Forth然と
  した」を名乗りつつ`>R`/`R>`を欠く状態がフェーズ1の間続く。

## 宿題

- `スタック表示`の具体的な表示順（下から上／上から下）は未確定。
  実装時に決定する。
- `nip`/`tuck`以外の合成語パターン（例：`over over`相当の`2over`）
  は今回検討していない。必要になった時点で追加検討する。
- リターンスタック（`>R`/`R>`）の導入は、評価器にもう1本スタックを
  持たせる構造的変更を伴うため、別途ADRで本格検討する。
- メタプログラミング機構（イミディエイトワード）の再検討は
  フェーズ2の議題として持ち越す。
