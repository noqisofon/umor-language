# ADR-0008: 辞書は追記のみ（線形リスト方式）— 自己言及的再定義における名前解決はForth本来の意味論に従う

## Status

Accepted

## Context

REPL上で以下の再定義を行ったところ、無限再帰によるスタックオーバーフロー（`STATUS_STACK_OVERFLOW`）でプロセスがクラッシュする事故が実際に発生した。

```
umor> 終了 とは、「これから REPL を終了します！！」と 表示して 終了する こと。
```

この定義の本体末尾にある`終了する`は、書き手の意図としては「（表示した後で）実際にREPLを終了させる、組み込みの終了処理を呼びたい」というものだったと推測される。しかし現在の辞書実装は「同じキー（ワード名）に対して新しい値を単純に上書きする」というHashMap的な意味論を採用しているため、本体の完成と同時に辞書上の`終了`エントリはユーザー定義のものに置き換わり、本体中の`終了する`もこの新しい定義自身を指すことになる。結果、`終了`を呼ぶたびに自分自身を呼び直す無限再帰となった。

ADR-0001（44行目）およびADR-0006では、いずれも「辞書は素直に上書きされる」ことを明示的な前提・仕様として述べている。これは実装上の見落としではなく、意図した設計判断だった。しかし今回の事故を踏まえ、この前提そのものを再検討する。

Forth系処理系（本家Forth、FICL等）の辞書は伝統的にHashMapではなく**連結リスト**であり、`：新語 ... ；`は既存の同名エントリを破棄せず、リストの先頭に新しいエントリを追加するだけである。名前解決（辞書引き）は常にリストの先頭から線形に探索されるため、見かけ上は「最新の定義が有効」に見えるが、これは上書きではなく**シャドーイング（多重定義＋優先順位探索）**である。

この差が決定的な意味を持つのは、まさに今回のような自己言及的な再定義の場面である。Forthでは、新しい`：FOO ... ；`のコンパイルが完了する（＝リストに新エントリが追加される）までの間、本体中に登場する`FOO`という語は、その時点でまだ辞書に存在する**古い方のFOO**として解決される。新しいFOOエントリ自身は、まだ自分の本体をコンパイルしている最中は辞書に存在しないため、自己参照のしようがない。

このセマンティクスをUmorに採用した場合、今回の事故は次のように解決される。

```
終了 とは、「これから REPL を終了します！！」と 表示して 終了する こと。
```

この本体中の`終了する`は、定義完了前の時点で辞書引きされる（あるいは定義完了前の辞書状態に束縛される）ため、**組み込みの（古い）`終了`**を指す。結果、「表示してから実際にREPLを終了する」という、書き手が本来意図していた通りの動作になる。

## Decision

辞書の意味論を、単純上書き（HashMap的）から、Forth本来の**追記専用・線形探索方式**に変更する。

1. **辞書はエントリの追記のみを行い、削除・上書きは行わない**。実装上はVecやリンクリストなど、追加順を保持できる構造を用いる。
2. **名前解決（ワード呼び出し時の辞書引き）は、最も新しく追加されたエントリから順に探索し、最初に一致したものを採用する**。これにより、複数回再定義されたワード名は、実行時には常に「一番新しい定義」が使われるという、従来のHashMap的な上書きと見かけ上同じ挙動を提供する。
3. **定義中の自己参照（同名ワードの呼び出し）は、その定義が辞書に追加される前の時点での辞書状態に対して名前解決される**。つまり、ある単語の本体をコンパイルしている最中に登場する自分自身の名前は、古い（あるいは存在しない）エントリを指す。定義がまだ存在しない新規ワード名（前方参照なし）の場合、これは未定義語エラーとなる。

この名前解決のタイミングは、実装上は「定義の構文解析・コンパイルが完了し、辞書へのpushが行われるタイミング」を境界とする。境界より前に本体内で行われる名前解決はすべて旧辞書状態を参照し、境界より後（＝定義完了後、そのワードが実際に呼び出される段階）でのみ新しい定義自身が辞書に存在する状態になる。

## Consequences

**得られるもの**：

- 自己言及的な再定義（`終了 とは ... 終了する こと`のような、既存ワードの前後に処理を挟み込む典型的なイディオム）が、ネイティブスタックオーバーフローという最悪の失敗モードではなく、書き手の意図通りに動作するようになる。
- Forth系言語の伝統的な辞書意味論との整合性が取れる。ADR-0001が既に「Forthの『辞書は常にユーザーに開放される』という思想」を参照していたことと矛盾しない、より深いレベルでの一貫性が得られる。
- 「今の辞書の中身だけで動作が説明できる」というADR-0001の思想は保たれる。ただし「今の辞書の中身」の意味が、単一の最新状態のスナップショットではなく、「追記された全エントリのうち、探索順で最初に見つかったもの」という定義に精緻化される。

**トレードオフとして受け入れるもの**：

- **メモリの単調増加**：REPLで同じワードを何度も再定義すると、古いエントリは辞書から消えずに残り続ける。長時間のREPLセッションでは、辞書サイズが再定義回数分だけ増加していく。ただし通常の利用（ファイル実行）では大きな問題にならないと想定される。
- **辞書検索が線形探索になる**：エントリ数が増えると理論上は探索コストが増す。実用上は数百〜数千エントリ程度では問題にならないと想定されるが、パフォーマンスが問題になった場合は「名前→最新エントリへの索引」を別途キャッシュとして持つハイブリッド実装（追記自体はリストのまま、検索だけHashMapで高速化）を検討する余地がある。
- **「本当に古い定義を明示的に呼びたい」ケースへの対応は範囲外**：Forthの一部方言にある、古い定義に明示的にアクセスする構文（例：即値による直接束縛）は、フェーズ1では導入しない。自己言及的な再定義における暗黙の「古い定義への解決」のみをサポートする。
- ADR-0001・ADR-0006中の「辞書は素直に上書きされる」という記述は、本ADRにより意味論的に訂正される（上書きに見えるが実装は追記＋シャドーイング）。両ADRの**結論**（REPLコマンドは辞書引きより優先しない、`終了`は再定義可能）自体は変更されない。
