# ADR-0015: 変数宣言の`は`は直前スペース必須（構造キーワードのまま） — レビュー指摘は実装バグではなく仕様通り

## Status

Accepted

## Context

Julesさんによる実装コードベースレビュー（2026-09週）で、次の指摘が
あった。

> `try_variable_decl`では`Word("x"), Word("は"), Word("変数")`の
> 順にトークンが並んでいる場合のみ変数宣言と判定する。空白なしの
> 「Xは 変数」と書いた場合、字句解析器で「は」が送り仮名として
> 削られて`Word("x")`と`Word("変数")`になるため、変数宣言とは
> 認識されない。

この指摘を受けて、「`Xは 変数`（`X`と`は`の間に空白なし）で
変数宣言を書きたかったのに、できないのはバグではないか」という
疑問が持ち上がった。

議論の結果、次の点が確認された。

1. ワード定義構文（`ほげほげ とは、～こと。`）は、そもそも
   `ほげほげ`と`とは`の間に**現行の実装・運用として常にスペースが
   入る**ことで成立している。「`ほげほげとは`とくっつけて書きたい」
   という理想はあったが、これは現状の実装ではなく将来の願望に
   すぎず、現行運用は既にスペース必須で回っている。
2. `は`による変数宣言（`Xは 変数`）を、`X`と`は`の間の空白なしで
   書けるようにしたい、という当初の意図があった。しかしこれを
   実現しようとすると、根本的な問題にぶつかる：`Xは`を1つの字句と
   見て`は`だけを構造キーワードとして剥がす処理を入れたとしても、
   **剥がした後に残る`X`こそが変数名として使われる**ため、結局は
   「`は`を独立したトークンとして切り出す」処理が必要になり、
   それは実質的に空白区切りと同じことをレキサー内部でやり直して
   いるにすぎない。
3. `ほげほげは 変数`と書いた場合、`は`をくっつけたまま送り仮名的に
   処理してしまうと、変数名が`ほげほげは`という（助詞込みの）
   おかしな名前になってしまう。これは`とは`の場合に`ほげほげとは`
   から`ほげほげ`という正しいワード名を切り出す必要があるのと
   全く同じ構造の問題であり、`とは`が既にスペース必須という
   妥協で運用している以上、`は`だけ例外的にくっつけ書きを実現する
   理由がない。

結論として、`は`を`とは`と同様「直前スペース必須の構造キーワード」
として扱う**現行の実装は仕様として正しく**、Julesさんが指摘した
挙動はバグではない。

## Decision

変数宣言構文における`は`は、`とは`・`ならば`・`つぎに`・
`そうでなければ`・`変数`・`本体`と同じ「直前スペース必須」の
構造キーワードのままとする。実装（`try_variable_decl`が
`Word, Word("は"), Word("変数")`の3トークン列を要求する挙動）は
変更しない。

正しい変数宣言の書き方は：

```umor
ほげほげ は 変数
```

であり、

```umor
ほげほげは 変数
```

は変数名が`ほげほげは`になってしまう（あるいは構造キーワードとして
認識されず変数宣言自体が成立しない）ため、**意図的にサポートしない**。

これは`とは`によるワード定義構文（`ほげほげ とは、～こと。`）が
`ほげほげ`と`とは`の間に空白を要求しているのと完全に対応する制約
であり、`は`だけを特別扱いして送り仮名的にくっつけ書きを許す
非対称なルールを導入しない、という一貫性を優先した判断である。

## Consequences

**得られるもの**：

- `とは`と`は`という、役割の近い2つの構造キーワード（どちらも
  「名前を宣言する」構文の一部）が、スペース要件について
  一貫したルールに従うことになる。
- 変数名・ワード名の切り出しロジックがどちらも「構造キーワードの
  前で区切る」という単純な原則のみに従い、送り仮名処理との
  特別な相互作用（`は`だけ剥がす／剥がさないの分岐）を持たずに済む。
  実装がシンプルなまま保たれる。

**トレードオフとして受け入れるもの**：

- 日本語の助詞としての`は`の自然な使い方（名詞に膠着する）を
  Umorの構文としては再現できない。`Xは`と書きたくなる直感的な
  誘惑は今後も繰り返し起こりうる。
- **本ADRの主目的**：この「`Xは 変数`と書けないのはバグではないか」
  という疑問は、設計者自身が将来再び同じ疑問を持つ可能性が高いと
  判断されたため、単なる補足ではなく、経緯を追跡できる形で
  明文化することを主眼として本ADRを作成した。
