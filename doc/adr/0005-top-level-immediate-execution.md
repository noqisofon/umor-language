# ADR-0005: トップレベルにワード定義だけでなく即時実行式を許す

## Status

Accepted

## Context

これまでのUmorは、トップレベルに「ワード定義」（`〈単語〉 とは 〜 こと。`）
しか書けなかった。しかしFORTHには、コロン定義（`: NAME ... ;`）以外の
場所に書かれたワード列は、その場で即座に実行されるという重要な特徴が
ある。トップレベルに`7 3 + .`と書けば、定義なしにその場で計算されて
結果が表示される、という対話的な性質である。

この性質がUmorになければ、次のような素朴なコードすら書けない。

```umor
「こんにちは、世界！」を 表示する
```

ワード定義の中でしか式を書けないという制約は、以下を実現する上での
障害になっていた。

- ファイルを渡して実行する、素朴なスクリプト実行
- REPL（対話環境）——ユーザーが1行入力するたびに、その場で
  意味のある結果を返す必要がある

## Decision

トップレベルに、ワード定義に加えて**即座に評価器によって実行される
「式の列」**も書けるようにする。

```umor
「こんにちは、世界！」を 表示する。

挨拶する とは、
    「こんにちは」を 表示する
こと。

「デバッグ中」を 表示する。
```

上記で`挨拶する とは 〜 こと。`は今まで通り辞書に登録されるだけ
（実行されない）。それ以外の式の列は、パースされ次第その場で実行される。

**`。`の役割拡張**：

- トップレベルの式の列も`。`で終端する
- **ワード定義の`body`（本体）の中では、`。`の使用を禁止する**
  （構文エラーにする）

これにより、`。`が現れた時点で「それが何を閉じているか」という
曖昧さが生まれない。`。`は常に「今開いている一番外側の塊
（ワード定義、またはトップレベルの式の列）を閉じる」という
1つの意味しか持たない。

**実行モデルの変更（パースと実行の統合）**：

これまでの「ソース全体を一度にパースしてASTを作り、その後で実行する」
という2段階分離をやめ、次の逐次処理ループに変える。

```
ソースの先頭から読む
  ↓
次の塊（ワード定義 or トップレベル式）を1つパースする
  ↓
ワード定義なら → 辞書に登録するだけ（実行しない）
トップレベル式なら → 即座に評価器で実行する
  ↓
ソースの終わりまで繰り返す
```

これはバイトコードVMのような「まず全体をコンパイルしてから実行する」
方式とは異なり、素朴なツリーウォークインタプリタの実装としては
自然な選択である。この「読みながら実行」モデルは、ファイル実行と
REPLの両方で同じコアループを共有できる（ファイル実行は「入力ソースが
ファイル全体」、REPLは「入力ソースが1行ずつ届く」という違いに
すぎない）。

## Consequences

**得られるもの**：

- FORTH本来の対話的な実行モデルにUmorが近づき、ワード定義なしの
  素朴なスクリプトが書けるようになる
- ファイル実行・REPLが同じ実行コアを共有できるため、二重実装を
  避けられる
- `。`の意味が「今開いている一番外側の塊を閉じる」という1つに
  統一され、曖昧さが生まれない

**トレードオフとして受け入れるもの**：

- 既存のパーサー実装（`parse(tokens) -> Program`という、全体を
  一度に構文木化する設計）に手を入れる必要がある。`Program`の
  構造を「ワード定義」と「トップレベル式」を区別できる形
  （`TopLevelItem`のような列挙型）に拡張する必要がある
- ワード定義の`body`の中で`。`を使おうとすると構文エラーになる、
  という新しい制約が増える（ただし、これは曖昧性を排除するための
  意図的な制約であり、既存のワード定義構文（`本体とは`必須ルール等）
  とは矛盾しない）
