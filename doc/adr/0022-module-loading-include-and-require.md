# ADR-0022: モジュール読み込み機構 — `含める`と`必要`

## Status

Accepted（impl-0032で実装。宿題は本ADRの更新として解決済み）

## Context

Umorにはまだファイル分割・ライブラリ読み込みの機構がない。
将来のAGC（Adventure Game Construction）構想や、curses的な
TUIバインディングをはじめとする「バンドルライブラリ」の
読み込みを見据えると、モジュールシステムがどこかの時点で
必要になる。

Forth系言語の伝統的な語彙である`INCLUDE`（無条件に毎回読み込む）
と`REQUIRE`（未読み込みならロード、読み込み済みならスキップする
一度きり保証）に相当する日本語ワードとして、以下が提案された。

```
「./honi.umor」を 含める。
「./honi.umor」が 必要。
```

助詞の使い分け（`を`／`が`）は、`含める`が能動的な操作
（対象を取り込む）であるのに対し、`必要`が状態の要求
（これが要る、という宣言）である点と対応しており、
日本語話者の直感とも合っている。

## Decision

以下の2ワードをモジュール読み込み機構の入り口として導入する。

- **`「path」を 含める`**：対象ファイルを無条件に読み込んで
  その場で評価する。Forthの`INCLUDE`相当。
- **`「path」が 必要`**：対象ファイルが未読み込みであれば
  読み込み、読み込み済みであればスキップする。Forthの
  `REQUIRE`相当。

現時点では両ワードの存在と大まかな意味論のみを決定する。
実装の詳細判断は次の「宿題」として保留する。

## 宿題（解決済み・impl-0032）

- **`必要`の重複読み込み判定方法**：`Interpreter`に
  `loaded_paths: HashSet<String>`を持たせ、`必要`が読み込む直前に
  （正規化後の）パスをここへ挿入する。辞書やモジュール専用の
  グローバルレジストリではなく、インタプリタのインスタンス状態
  として素朴に持つ（`Interpreter`はプロセス内に1つが前提のため、
  これで十分）。`含める`はこの集合を一切参照・更新しない
  （無条件読み込みという意味論そのものなので、判定不要）。
- **パス正規化**：`./honi.umor`と`honi.umor`は同一ファイルとして
  扱う。ただし正規化は「先頭の`./`を1回だけ剥がす」という最小限の
  処理にとどめ、`../`・絶対パス・区切り文字（`/`と`\`）の差異には
  対応しない。これらは実際に必要になった時点で改めて設計する
  （実装時点でのスコープ外・意図的な先送り）。
- **相対パスの基準点**：プロセスのカレントディレクトリからの相対
  （`std::fs::read_to_string`の既定動作をそのまま使う）。実行中の
  スクリプトファイルからの相対パス解決は行わない。CLIの利用形態上
  「プロジェクトルートで実行する」運用を前提とし、この単純な挙動で
  当面まかなえると判断した。
- **将来のバンドルライブラリ参照との関係**：本impl-0032のスコープ
  外。`"curses"`のようなライブラリ名の解決ロジックは、実際に
  バンドルライブラリを導入する段階で別途ADRを起こして扱う。

## Playground（WASM）非対応の明記

`含める`／`必要`はいずれも`std::fs::read_to_string`によるファイル
読み込みを介するため、ブラウザ上で動くPlayground（wasm32ターゲット、
ADR-0027）では実質的に機能しない。

- ファイルシステムの抽象化（例えば`ModuleLoader`トレイトを設けて
  CLIでは実ファイルシステム、Playgroundでは埋め込みリソースや
  未対応エラーに差し替える、といった設計）は今回は行わない。
  CLI専用機能と割り切る。
- そのためwasm32ターゲット向けの`#[cfg]`分岐や特別なエラー処理も
  追加しない。`std::fs::read_to_string`はwasm32-unknown-unknown上でも
  コンパイルは通り、実行時に単に失敗するだけなので、`含める`／`必要`は
  `ModuleReadError`を返す（クラッシュはしない）。Playground利用者に
  とっては「モジュール読み込みワードを使うと常にエラーになる」という
  分かりやすい挙動になる。
- 将来Playgroundでもモジュール読み込みが必要になった場合は、
  ファイルシステム抽象化を含む設計を別ADRとして起こす。

## Consequences

**得られるもの**：

- ファイル分割・ライブラリ読み込みという、AGC構想やバンドル
  ライブラリ構想の前提となる機構に、最小限の語彙的な出発点が
  与えられる。
- `含める`（毎回評価）と`必要`（一度きり保証）という意味論の
  違いをワードレベルで最初から区別しておくことで、後から
  「重複読み込み時の挙動をどうするか」で揉める余地を減らせる。

**トレードオフとして受け入れるもの**：

- パス正規化は「先頭の`./`を1回剥がすだけ」の最小実装であり、
  `../`・絶対パス・区切り文字の差異には対応しない。表記ゆれが
  残るケースでは`必要`が別ファイル扱いになりうる。
- モジュールシステムとしての全体設計（名前空間分離をするか、
  読み込んだワードがグローバル辞書にそのまま追記されるのか等）
  には踏み込んでいない。今回は`含める`・`必要`という2つの
  ワードの導入のみを扱う、意図的に薄いADRである（現状は
  読み込んだ定義がそのままグローバル辞書に追記される＝
  名前空間分離なし）。
- Playground（WASM）では`含める`／`必要`が実質使用不可（常に
  `ModuleReadError`になる）。CLI専用機能と割り切った結果であり、
  ファイルシステム抽象化は将来必要になった時点で別ADRとして扱う。
