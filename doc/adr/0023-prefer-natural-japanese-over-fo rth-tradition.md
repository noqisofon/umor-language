# ADR-0023: 設計原則 — 実装コストが過大でない限り、日本語としての自然さを優先する

## Status

Proposed

## Context

助詞切り出し（`ほげに 42を 入れる。`のような、名詞に助詞が
くっついた書き方をどう扱うか）を検討する中で、次の3例が
判断材料として挙げられた。

```
ほげに 42を 入れる。   （日本語として正しい・意図も正しい）
ほげを 42に 入れる。   （日本語として正しいが、おそらく意図が違う）
ほげく 42で 入れる。   （日本語としておかしい）
```

この検討の過程で、Umorという言語の根本的な立ち位置に関わる
方針が確認された：Umorは単にForthの語彙を日本語に置き換えた
言語ではなく、**「日本語Forth」として、日本語としての自然な
書き方を優先する言語でありたい**、という意図である。

これまでのADR群でも、この方針に沿う判断・沿わない判断の
両方が既に存在する。

- **沿う判断の例**：助数詞のUmor方式（spec 2章）。Mind方式の
  「読み飛ばし」ではなく、`5000円`のように数値に助数詞が
  自然にくっつく書き方を、Value Objectの構築という形で
  正面から意味づけている。
- **沿わない（沿えなかった）判断の例**：ADR-0015の`は`。
  「`ほげは 変数`のようにくっつけて書きたい」という日本語
  としての自然な欲求はあったが、剥がした後の残りが正しい
  名前になることを保証しようとすると、実装上スペース区切りと
  同じ処理をレキサー内でやり直すことになり、本質的な困難に
  ぶつかったため、直前スペース必須という妥協に至った。

助詞切り出しの検討により、「日本語として自然に書きたい」という
欲求が今後も繰り返し出てくること、またその都度「今回はADR-0015の
`は`のケースと同じ壁にぶつかるのか、それとも助数詞のケースの
ように実現できるのか」を個別に見極める必要があることが
はっきりした。この判断基準を毎回ゼロから議論するのではなく、
原則として先に明文化しておく方が今後の設計効率が良いと判断した。

## Decision

Umorの文法・書き方に関する設計判断において、以下を優先順位の
原則として採用する。

1. **日本語として自然に読み書きできるかを最優先の判断基準とする。**
   Forthの伝統的な語順・記法をそのまま日本語に置き換えるのではなく、
   日本語話者にとって自然な書き方を実現できないかをまず検討する。

2. **ただし、実装が過度に複雑になる、または既存の正規化パイプラインの
   秩序を崩す場合は、この限りではない。** 「実装が難しい」かどうかの
   目安は都度議論するが、ADR-0015の`は`のように、くっつけ書きを
   実現しようとした結果「剥がした後に残る部分が本当に正しい名前・
   語幹になることを保証できない」という本質的な困難にぶつかる場合は、
   スペース区切り等の妥協を許容する。

3. **この原則は既存の判断を遡って覆すものではない。** ADR-0015の
   `は`の扱いは、実装困難を理由にした正当な妥協として維持される。
   本ADRは、今後同種のトレードオフに直面したときに参照する
   判断基準を明文化するものであり、個別のADRの内容を変更しない。

4. **助詞切り出しの検討は、本原則のもとで別途ADR化する。**
   助詞（`は・が・を・に・へ・と・で・から・より・まで`等）は
   有限集合であり末尾一致による機械的な切り出しが可能と見込まれる
   ため、ADR-0015の`は`（構造キーワード）とは事情が異なる可能性が
   ある。実現可能かどうかは別ADRで検討する。

## Consequences

**得られるもの**：

- 「日本語らしい書き方を実現したい」という欲求と「実装コストを
  抑えたい」という制約が対立したときに、都度ゼロから哲学的な
  議論をする必要がなくなる。優先順位が先に決まっているため、
  個別ADRのContextでは「この原則に照らしてどちらに転ぶか」だけを
  検討すればよい。
- ADR-0015（`は`の妥協）と、今後実現されるかもしれない助詞切り出し
  ワードの扱いが「一貫性のない場当たり的な判断」ではなく「同じ
  原則のもとでの異なる結論」として説明可能になる。
- Umorが「日本語Forth」を名乗る以上の、具体的な設計指針として
  機能する。

**トレードオフとして受け入れるもの**：

- 「実装が過度に複雑」の基準が曖昧なままであり、境界線上の
  ケースでは今後も個別に議論が必要になる。本ADRはその議論の
  出発点を与えるに留まり、機械的な判定基準を提供するものではない。
- 日本語としての自然さを優先する方針は、場合によっては実装の
  一貫性・単純さとのトレードオフを継続的に生み出す。処理系が
  複雑化するリスクは今後も都度検討する必要がある。
