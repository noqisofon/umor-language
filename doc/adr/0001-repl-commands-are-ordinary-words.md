# ADR-0001: REPLコマンド（`終了`等）は辞書引きより優先させない

## Status

Accepted

## Context

UmorのREPLには`終了`・`さよなら`のような、REPLプロセス自体を
終了させるための語が必要になる。実装の初期段階では、これらを
「辞書引きより手前で判定される、専用のREPLコマンド層」として
実装していた。

この実装を実際に動かして確認したところ、次の事故が起きることが
判明した。

```
umor> 終了 とは、「これからREPLを終了します！」と 表示すること。
umor> 終了
```

1行目の`終了`再定義はエラーなく受理される。しかし2行目で
実際に`終了`を実行すると、再定義した内容（表示文の出力）は
一切実行されず、元のREPL終了動作がそのまま発動してREPLが
終了してしまう。

これは「定義は通ったのに、定義した通りには動かない」という、
処理系の振る舞いとして最も避けたい種類の食い違いである。
ユーザーから見ると、再定義がエラーにも警告にもならず黙って
無視される（正確には、無視されるのではなく別レイヤーの動作に
先取りされる）ため、原因の特定が非常に困難になる。

さらに、この専用コマンド層は「辞書引きが唯一の解決経路である」
という、4.2節・4.3節で重視してきた「先読み不要な単純パーサー」の
設計哲学とも衝突する。辞書引きの手前に別のディスパッチ層を
持ち込むことは、Umor全体の設計判断の一貫性を崩す。

## Decision

`終了`・`さよなら`等のREPL脱出コマンドは、専用のコマンド層を
持たない。これらは最初から組み込み辞書に登録された、**通常の
ワードの1つ**として提供する。

- ユーザーがこれらのワードを再定義すれば、辞書は素直に
  上書きされる。以後`終了`と打てば再定義後の動作が実行され、
  REPLを終了する効果は失われる（再定義した以上、当然の帰結
  として許容する）
- 辞書引きが常にただ1つの解決経路になるため、ワードの動作は
  常に「今の辞書の中身」だけで説明できる
- ただし、`終了`が上書き可能である以上、ユーザーが誤って
  （あるいは意図して）再定義した場合に備え、**辞書を一切
  経由しない、常に確実にREPLを抜けられる脱出手段**を
  REPLの入力ループ自体に直接実装しておく
  （例：Ctrl+DによるEOFシグナル、Ctrl+Cによる割り込みなど）。
  これはワードではなくREPLループのプログラム的な仕組み
  そのものなので、ユーザー定義によって上書きされる余地が
  そもそもない

## Consequences

**得られるもの**：

- REPLディスパッチに特殊優先ルールが存在しなくなり、
  「辞書引きが唯一の解決経路」という一貫した動作モデルになる
- ワードの振る舞いが常に「今の辞書の中身」だけで説明可能になり、
  デバッグ時の驚き（今回発覚したような食い違い）が構造的に
  起きなくなる
- Forthの「辞書は常にユーザーに開放される」という思想、および
  Umorがこれまで重視してきた「先読み不要な単純パーサー」の
  哲学と一貫する

**トレードオフとして受け入れるもの**：

- ユーザーが`終了`を再定義すると、そのワード経由でのREPL終了は
  できなくなる。これは意図した仕様であり、バグではない
- 辞書を経由しない脱出手段（Ctrl+D等）を必ず1つ以上、REPL
  ループの実装として別途用意する必要がある。これを怠ると、
  ユーザーが`終了`を再定義した場合にREPLから正常に抜ける
  手段がなくなる
