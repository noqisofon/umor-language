# ADR-0000: ADR（Architecture Decision Records）の記述フォーマットと運用指針

## Status

Accepted

## Background

Umor では、言語設計判断やアーキテクチャ上の決定を記録するために ADR（Architecture Decision Records）を導入している。
これまでは標準的な形式（Context / Decision / Consequences）を用いていたが、言語機能の拡充に伴い、Context セクションに前提知識・起きた事象・検討理由が混在して長大化する傾向があった。

## Circumstances

ADR-0001 から ADR-0031 までの運用を振り返ったところ、以下の課題が明確になった：

1. **Context の混濁**: 「言語の前提知識」「直面した具体的な事故やトリガー」「選択肢の比較検討」が 1 つのセクションに同居し、論点の把握が難しくなっていた。
2. **「なんとなく」「好み」の居場所の不在**: プログラミング言語設計において、「強い理論的理由はなく、作者の直感や好み、あるいは一旦動かすための暫定」という判断がしばしば発生する。理由がないことを明記する枠がなかったため、後から深読み・過度な忖度を招くリスクがあった。
3. **実装状況の追跡**: 決定時点と実装完了時点でタイムラグがあり、宿題がどう解決されたかやテストとの対応を追記する共通の場所が必要とされていた。

## Rationale

- 前提・事象・判断を明確に分離するため、従来の Context を **Background**（前提・制約）、**Circumstances**（起きたこと・トリガー）、**Rationale**（判断基準・比較）の 3 段階に分割する。
- Rationale には「特に理由なし／作者の好み」「フェーズ1の暫定措置」も正直に書いてよいことを公式ルール化する。これにより、将来の不要な迷いや深読みを防ぐ。
- Decision は Rationale から機械的に導出される結論として簡潔に記述する。
- 実装完了時には `## 実装状況（YYYY-MM-DD）` セクションを追記し、決定とコードの乖離を最小限に抑える運用とする。

## Decision

今後新規に作成する ADR は、以下のテンプレートフォーマットに準拠して記述する。
ファイル名は `0001-` 以降の連番とソート順を揃えるため、4桁ゼロパディングの `0000-adr-template.md` とする。

---

### ADR 記述用テンプレート

以下をコピーして新規 ADR の雛形として使用する。

```markdown
# ADR-XXXX: （タイトル）

## Status

Proposed / Accepted / Deprecated / Superseded

## Background
（そもそもなぜこの決定が必要になったか。前提となる状況・制約・これまでの設計方針）

## Circumstances
（その時点で具体的に何が起きていたか。エラーやクラッシュの発生、書けなかったコード例、検討された選択肢などの直接のトリガー）

## Rationale
（Circumstancesからどう判断したか。判断基準・優先順位。「特に理由なし／作者の好み」「フェーズ1の暫定」もここに正直に書く）

## Decision
（結論。Rationaleから機械的に導出される構文仕様、パーサー・評価器の挙動など）

## Consequences（任意）
（この決定によって何が得られ、何をトレードオフとして諦めたか）

## 宿題・未解決事項（任意）
（決定時点で未解決のまま残すエッジケースや、フェーズ2へ先送りする論点）

## 実装状況（YYYY-MM-DD）※実装完了時に追記
（実装した関数・ASTノード、テスト名、宿題の着地点など）

## References
（関連するADR、スペック該当節、参考資料リンクなど）
```

---

## Consequences

**得られるもの**：
- 思考プロセス（前提 → 契機 → 判断 → 結論）が一貫した流れで整理され、執筆しやすく読みやすくなる。
- 「特に理由なし／好み」を明記できるため、将来の設計変更時の心理的ハードルが下がり、過剰な忖度を防止できる。
- 実装状況セクションの定型化により、ドキュメントとコードの乖離を容易に検知・追跡できる。

**トレードオフとして受け入れるもの**：
- 既存の ADR-0001〜0031 は従来の Context 形式で書かれており、当面は新旧フォーマットが混在する。過去の ADR を無理に一括移行する必要はなく、新規 ADR から順次適用する運用とする。
