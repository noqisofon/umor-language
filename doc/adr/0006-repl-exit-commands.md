# ADR-0006: REPL終了コマンド `終了`/`さよなら` の具体的な導入

## Status

Accepted

## Context

ADR-0005でトップレベル即時実行式とREPLの実行コアが定まったことを受け、
REPLを実際に終了させる手段が必要になった。

検討の初期段階では、`終了`・`さよなら`をREPLの入力ループ自身が
生の入力行を見て特別に判定する、辞書引きより手前の専用コマンド層として
実装する案を検討していた。しかし、これは既にADR-0001で検証済みの案
であり、実際に動かして確認したところ次の事故が起きることが判明していた。

```
umor> 終了 とは、「これからREPLを終了します！」と 表示すること。
umor> 終了
```

`終了`を再定義しても、専用コマンド層が辞書より先に反応してしまい、
再定義した内容が一切実行されずにREPLが終了してしまう。これは
ADR-0001で「辞書引きが唯一の解決経路であるべき」という結論に至り、
却下された設計である。

## Decision

ADR-0001の結論をそのまま踏襲し、`終了`・`さよなら`を次の2層構造で
実装する。

1. **通常のワードとして辞書に登録する**：`終了`・`さよなら`は
   組み込みの基本ワードとして最初から辞書に存在する。ユーザーが
   これらを再定義すれば、辞書は素直に上書きされる
2. **辞書を経由しない、確実な脱出手段をREPLループ自体に用意する**：
   `Ctrl+D`（標準入力のEOF）で、辞書の状態に関わらず常にREPLを
   終了できるようにする

`終了`・`さよなら`ワードの実行内容は、評価器の通常の
`Result<(), RuntimeError>`の枠組みでは表現できない「REPLループを
止める」という制御を必要とする。このため、評価器に「実行を打ち切って
呼び出し元（REPLループ）に制御を返す」ための特別な信号
（例：`RuntimeError`とは別の`ControlSignal`のようなenum、または
`Result`の第3の選択肢）を用意し、`終了`・`さよなら`ワードの
ネイティブ実装がこれを返すようにする。

ファイル実行時にこれらのワードが呼ばれた場合は、その時点で
ファイルの残りの処理を打ち切って正常終了する（REPLと同じ
「実行を打ち切る」という意味を、ファイル実行の文脈にもそのまま
適用する）。

## Consequences

**得られるもの**：

- ADR-0001の結論（辞書引きが唯一の解決経路）と矛盾しない、
  一貫した設計になる
- ユーザーが`終了`を再定義した場合の挙動が予測可能になる
  （再定義すればその内容が実行され、REPL終了効果は失われる。
  これは意図した仕様）
- `Ctrl+D`という辞書に依存しない脱出手段が必ず存在するため、
  ユーザーが誤って`終了`を再定義してしまっても詰まない

**トレードオフとして受け入れるもの**：

- 評価器に「通常の値の返却」以外の制御信号（実行の打ち切り）を
  持たせる必要があり、`RuntimeError`だけで完結していたエラー
  ハンドリングの設計に手を入れることになる
- ファイル実行中に`終了`が呼ばれた場合、それ以降の処理が
  一切実行されなくなる。これは`終了`という名前から自然に
  予期される挙動ではあるが、実装時にテストケースとして
  明示的に確認しておく必要がある
