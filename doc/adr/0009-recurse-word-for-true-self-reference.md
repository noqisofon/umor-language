# ADR-0009: `再帰`ワードの導入 — 真の自己再帰は名前解決に頼らず専用ワードで表現する

## Status

Proposed

## Context

ADR-0008により、辞書は追記専用・線形探索（新しい順）方式を採用することになった。これにより、次のような「既存ワードの前後に処理を挟み込む」再定義イディオムが安全に書けるようになった。

```
終了 とは、「これから REPL を終了します！！」と 表示して 終了する こと。
```

この本体中の`終了する`は、この定義自身が辞書に追加される前の辞書状態、すなわち1世代前の`終了`（この場合は組み込みの終了処理）に解決される。これは意図的な設計であり、正しく機能する。

しかし、この設計には論理的な帰結として次の制約が伴う：**ある定義の本体中に、自分自身と同じ名前を書いても、それは決して「今まさにコンパイル中の、この定義自身」を指すことができない。** 名前解決の対象は常に「1世代前まで」に限られるため、同名参照によるものは原則として旧世代の定義（それが存在しなければ未定義語エラー）に解決される。

これは再定義イディオムにとっては都合が良い一方、**真の自己再帰**（今コンパイル中の処理単語が、自分自身を繰り返し呼び出すことで反復処理を行いたい、というごく一般的なニーズ）を、同名のワード呼び出しでは原理的に表現できないことを意味する。たとえば階乗やハノイの塔のような典型的な再帰アルゴリズムを素直に書こうとすると、本体中で自分の名前を書いても、それは自分自身ではなく旧世代の（多くの場合は存在しない）定義を指してしまい、意図通りに動作しない。

Forth（ANS Forth標準）は歴史的にまったく同じ問題を抱えており、これに対して`RECURSE`という専用のimmediateワードで解決している。`：FOO ... FOO ... ；`と書くと本体中の`FOO`は（コンパイル完了前のため）古い`FOO`を指してしまうが、`：FOO ... RECURSE ... ；`と書けば、`RECURSE`は常に「現在コンパイル中の定義自身」への参照を生成する。

**ここでForthにおける`RECURSE`・`IF`・`THEN`・`;`等の正体を整理しておく**。これらはコンパイラにハードコードされた構文キーワードではなく、いずれも**IMMEDIATE属性を持つ、普通の辞書エントリ**である。IMMEDIATEワードは、通常のワードと異なり、コンパイルモード中であっても即座に実行される。実行された結果として、コンパイル中の定義に特定のバイトコードを埋め込んだり、コンパイルモードの状態を変更したりする。つまりForthには構文レベルでの予約語が実質存在せず、コンパイラ自体がユーザーによって拡張可能な、辞書ベースの機構として統一されている。

Umorはこの「IMMEDIATEワードによるコンパイラ拡張」という機構自体をADR-0004で（フェーズ1では）不採用と決めている。Umorの`ならば`・`つぎに`・`とは`・`。`等は、Forthのような辞書エントリではなく、**パーサーレベルでハードコードされた構文キーワード**として実装される（スペック4章・5章）。`再帰`をどちらの系列に位置づけるかは、ADR-0004との整合性を左右する設計判断になる。

## Decision

Umorに`再帰`という**構文キーワード**を導入する。ADR-0004の方針に合わせ、これを「辞書に登録されたワード」としてではなく、`ならば`・`とは`と同格の、パーサーが直接認識する予約構文トークンとして扱う。

- **`再帰`は辞書に一切登録されない**。したがって「再定義」という概念自体が最初から存在しない。`ならば`を再定義できないのと同じ理由で、`再帰`も再定義できない。ユーザーが`再帰`を処理単語名として定義しようとした場合は構文エラーとする。
- `再帰`は送り仮名正規化の対象となる（1.1節）。`再帰する`・`再帰し`・`再帰させる`等はいずれも正規化後`再帰`として扱われ、等価である。
- パーサーが「今コンパイル中の定義の中で`再帰`というトークンを見た」時点で、自己参照を表すASTノード（例：`Expr::SelfRecurse`）をその場に埋め込む。辞書引きは一切発生しない。
- `再帰`は処理単語本体の外（トップレベルや、まだどの定義本体にも属さない文脈）で使用された場合は構文エラーとする。
- 局所処理単語（4.2節）の本体中で`再帰`を使った場合は、その局所処理単語自身への自己再帰を意味する（親処理単語への再帰ではない）。

これにより、次のように書き分けが明確になる：

```
（再定義イディオム：旧世代の同名ワードを呼びたい）
終了 とは、「これから REPL を終了します！！」と 表示して 終了する こと。

（真の自己再帰：今コンパイル中の自分自身を呼びたい）
ハノイの塔 とは
    ・・・（ベースケース判定）・・・
    ならば
        ・・・
    そうでなければ
        ・・・ 再帰する ・・・
    つぎに
こと。
```

書き手は自分が今定義している処理単語の名前を本体中で改めてタイプする必要がなく、`再帰`と書くだけで自己再帰を表現できる。

## Consequences

**得られるもの**：

- ADR-0008が可能にした「安全な再定義イディオム」と、一般的な「自己再帰による反復処理」が、構文的に明確に区別された形で両立する。片方の設計判断がもう片方を妨げない。
- Forthの`RECURSE`と同じ発想を踏襲しつつ、実装はADR-0004の方針（IMMEDIATEワード機構を持たない）と矛盾しない形に落とし込める。`再帰`を辞書ベースのIMMEDIATEワードとしてではなく、`ならば`・`とは`と同格のパーサー予約構文として実装することで、2つのADRの間に緊張関係を生まない。
- `再帰`が辞書に登録されないことで、「再定義できるか／できないか」という問いそのものが発生しない。`ならば`や`とは`を再定義しようとする発想がそもそも出てこないのと同じ理由で、`再帰`についても迷いが生じない。
- 書き手が処理単語の名前を変更した場合でも、本体中の`再帰`は変更の影響を受けない（自分の名前をハードコードしていないため）、という副次的なリファクタリング耐性も得られる。

**トレードオフとして受け入れるもの**：

- `再帰`は他の構文キーワード（`ならば`・`とは`等）と同様、パーサーに直接組み込まれた特別扱いのトークンになる。辞書に載らないため、Umorの「基本ワード／標準ライブラリ」という2分類（既存メモ参照）のどちらにも属さない、**第3の区分（構文キーワード）**が存在することになる。この区分をスペックドラフトのどこかに明記しておく必要がある。
- パーサーは「現在コンパイル中の定義」というコンパイル時の状態を保持し、`再帰`の出現箇所でそこへの自己参照ノードを埋め込む処理を持つ必要がある。局所処理単語のネスト（4.2節）を考慮すると、この「現在コンパイル中の定義」はスタック的に管理する必要がある（親処理単語の中で局所処理単語をコンパイル中に`再帰`が出てきた場合、参照すべきは局所処理単語自身であり、親ではないため）。
- 相互再帰（`A`が`B`を呼び、`B`が`A`を呼ぶ）は`再帰`ワードでは表現できない。これは`再帰`の対象外であり、必要であれば通常のワード呼び出し＋前方宣言の仕組み（未検討）で別途対応することになる。
